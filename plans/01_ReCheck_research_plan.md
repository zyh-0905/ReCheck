# ReCheck：隐藏工具语义漂移下的决策敏感证据刷新

版本：研究设计 v1.0｜文献复核截至：2026-09-12

状态：拟研究方案。未完成实现、实验或理论证明；下述数字均为建议的预注册配置或继续投入门槛，不是实验结果，也不是会议录用标准。

## 1. 一句话选题

在连续任务中，工具接口不变但行为语义会变化。研究如何联合决定“验证哪条记忆、何时重新验证、验证结果可以复用多久”，最小化错误决策与完整执行成本，而不是每个任务重新验证全部记忆。

英文暂定标题：ReCheck: Decision-Sensitive Evidence Refresh for Agents under Hidden Tool Drift.

## 2. 为什么必须收紧创新边界

GLOVE 已经主动探测环境以重新校准记忆；SafeCommit 已经在行动前维护候选世界、执行定向探测并作出放行或回退决定；Grounding Agent Memory 已经给任务后的记忆维护器接入只读环境工具；When Stale Constraints Go Unchecked 已经诊断了有限验证预算分配失误。因此，不能声称首次主动验证记忆、首次预算化验证、首次按行动选探测。

拟验证的增量：把单次行动的验证扩展为连续任务中的可复用、会老化的证据管理问题，并给出跨任务成本摊销、漂移风险与任务损失共同决定的刷新策略。还必须比较传统 Age of Information / Age of Incorrect Information 和主动实验设计，而不只比较 LLM 提示基线。

## 3. 明确范围

主场景：本地数据库分析与可隔离的工具 API 工作流。冻结主代理；不先训练大模型。不研究真实资金操作、不声明任意开放世界安全性。

工具变化例子：金额单位、时间范围端点是否包含、时间戳时区、分页语义、状态枚举映射。当前工具 schema 不变；真实语义、变化时间和隐藏评测结果对代理不可见。

同一个变化对不同任务应有不同影响。例如金额单位变化影响总金额计算，但不一定影响订单数量统计。至少包含“确有变化但不影响当前任务”的反例组。

记忆不是假定由 oracle 正确写好：先让所有方法共享同一段正常任务前缀及形成的记忆，再进入漂移任务流。另设使用人工正确记忆的诊断组，区分初始记忆错误和时效错误。

## 4. 科学假设

H1：固定总成本时，决策敏感刷新优于年龄、熵或相似度驱动刷新。
H2：允许证据跨任务复用时，联合调度优于逐任务独立验证；随着任务复用率下降，优势应缩小。
H3：忽略证据老化会在漂移加快时失败；无限期复用不是合理基线。
H4：对无法通过现有只读工具区分的变化，算法应报告信息不足，而不能靠自信解决不可识别性。

## 5. 问题定义

令 z_t 为隐藏工具状态，q_t 为当前任务，b_t 为基于已见证据的状态信念；a_t 为任务动作；U_t 为本次选择的探测序列。

目标：

J(pi) = E[ sum_t { L(a_t,z_t,q_t) + lambda C_probe(U_t) + mu C_runtime(t) } ].

L 来自公开任务要求和场景模型；测试时不能读取隐藏答案来计算探测价值。模型内估计损失与最终隐藏评测损失必须分开保存。

理论轨：有限状态、已知或有可靠区间的转移/观测模型、限定时间窗、只读探测、明确误差假设。
实践轨：通过独立开发集拟合状态模型；有限候选生成可能漏掉真实机制。报告模型失配与候选覆盖，不把理论轨的保证迁移为开放世界保证。

## 6. 算法设计

### 6.1 数据对象

EvidenceRecord：claim_id、scope、source_receipt、checked_at、candidate_semantics、posterior_or_interval、dependency_ids、probe_cost。

Scope 至少包含工具、参数范围、实体类型与时间；一条探测只能更新其实际覆盖的范围。数据库时间戳或校验和不是语义正确性证明。

### 6.2 模块与接口

| 模块 | 输入 | 输出 |
|---|---|---|
| TaskDependencyExtractor | 当前任务、草案动作、记忆 | 候选相关前提及遗漏风险 |
| BeliefTracker | 历史探测、当前时间、局部模型 | 更新后的状态信念或候选集合 |
| ProbeFactory | 相关前提、公共工具描述 | 最多若干可执行只读探测 |
| RefreshPlanner | 信念、任务、预算、任务复用估计 | 探测、复用或回退决定 |
| EvidenceUpdater | 实际探测结果、范围 | 有范围的证据更新 |
| AgentAdapter | 经筛选的当前证据 | 交给冻结主代理的上下文 |

所有额外模型调用均计入成本。探测必须真的调用环境，不能把模型想象的工具返回当作证据。

### 6.3 从能实现的版本开始

先做小型有限语义模型，每个相关工具 2–4 个解释；通过训练环境可观察的校准探测拟合似然，测试时只知道备选机制、不知道当前真实机制。联合状态过大时使用局部因子和有限候选；单独报告截断错误。

在小状态设置用有限时域动态规划求模型内最优策略，作为诊断上界。部署版用短时域滚动规划：比较直接执行、多个候选探测及回退的预期总成本；执行首个动作后重新规划。考察规划深度 1、2、3，所有规划计算计入成本。

对探测 u 的近似价值可分解为当前任务的预期损失下降、未来复用的预期收益减去探测和维护成本。该分解是实现动机，不是默认最优性证明。未来任务分布只从已完成任务估计，不能看未来测试问题。

必须保留探测互补性测试：某些两个探测组合有用、单个探测无用。若只做单步贪心，应明确其局限。

## 7. 理论计划

### 7.1 可先证明的基础命题

若两个等概率隐藏状态在全部被动观测上不可区分、要求相反的二元动作，则不新增信息的策略平均错误率至少为 1/2。该事实仅用于论证问题必要性，不作为主要创新。

在同一信息条件下，若最近核验出错概率上界为 epsilon，之后 Delta 个时段每段条件变化概率上界为 h_bar，且未变化时保留的判断继续有效，则证据失效事件满足：

P(invalid at reuse) <= min(1, epsilon + 1 - (1-h_bar)^Delta).

这个联合界不是分布无关安全证书，也不约束主代理本身的推理错误。风险上界成立需要所声明的条件概率上界、正确范围和观测假设；若 h_bar 只是拟合值，必须额外处理估计错误。

### 7.2 论文真正应争取的理论贡献

在独立或弱耦合前提、受限转移模型和有界任务损失下，分析刷新阈值/滚动策略如何依赖任务损失、未来复用概率、探测成本与漂移率。小模型中求精确最优并验证结构；一般模型不默认存在阈值最优性或自适应次模性。

与 Age of Incorrect Information、EC2 和动态规划比较，区分已有定理的实例化与真正新增结果。若无法建立有信息量的算法界，可走机制驱动实证论文路线，不用空泛公式装饰“理论”。

## 8. 评测设计

### 8.1 三层数据

1. 机制层：拟 120 个独立环境流，每流 30 个连续任务；按环境/规则生成器划分为 40 开发、20 校准、60 测试。不得把同一任务流的不同轮次随机拆到不同集合。
2. 可执行层：至少数据库与工具 API 两类；不同变化组合、参数和任务模板保留到测试。
3. 外部层：MemoryArena 或 AppWorld 上的独立扩展，加原始未修改任务对照。扩展分数不称原始 benchmark 官方成绩。修改工具语义后必须重新验证任务目标仍一致、评测器没有继续使用旧语义。

初始数量只是预算起点。正式样本量根据不进入主结果的 pilot 估计效应方差和功效；以任务流为独立统计单位。

### 8.2 因子

漂移：无/低/高；通知：有/无；任务复用率：低/高；变化相关性：相关/无关；探测：确定性/有噪声；可识别性：可识别/不可识别。不要默认做巨大全因子笛卡尔积：优先预注册最能检验 H1–H4 的交互。

### 8.3 基线

必须运行：不刷新；固定周期 TTL；每次全量刷新；失败后刷新；同预算随机；按不确定性；决策前提优先提示；GLOVE；SafeCommit；逐任务独立探测；传统信息新鲜度/错误信息年龄策略；EC2 或适当主动实验设计基线。

最新任务后环境探测维护作为重要对照。代码无法复现时，标注本地实现或论文机制复现，不能冒称官方结果。所有基线得到相同工具、记忆、探测候选、模型和总预算。已知真实漂移位置/模型参数只能作为额外信息上界。

### 8.4 主指标

主图：有效完成率—端到端成本 Pareto 曲线。
另报累计任务损失、漂移后首次错误、错误行动率、拒绝率、无变化条件损害、探测次数、证据复用次数、延迟、token、工具和规划开销。

风险比例应给出分母：所有任务上的错误行动比例，与已执行任务中的条件错误率都要报告。不能用“拒绝全部执行”赢得主结果。

### 8.5 消融

去掉任务相关性、去掉老化、去掉跨任务复用、只做单步规划、随机未来复用估计、使用人工正确依赖/使用实际抽取依赖、无维护成本计费（仅作为错误口径诊断，不能做主结论）。

## 9. 统计与继续投入门槛

冻结主方法、预算档位和主要对照后，在独立测试上报告配对任务流 bootstrap 95% CI；多主假设采用预先声明的多重检验控制。闭源模型的运行日期、完整标识和缓存策略均固定并记录。

建议实质性门槛：有效完成率对最强等信息基线非劣（事先确定如 -2 个百分点的容忍边界），并降低至少约 20% 的端到端成本；或者同成本得到稳定的约 5 个百分点提升。门槛是研究决策用，不是领域统一发表标准；必须有 CI、跨任务外部验证和机制消融。

若加入规划维护成本后无收益、简单前提优先提示达到同样效果、只在已知漂移时刻有效，或主要靠拒绝任务降低风险，应停止扩大实验，修正主张。

## 10. 阶段交付

A：相关工作对照矩阵、隐藏语义场景、20–30 流 pilot、基础基线。
B：有限模型精确解、滚动刷新实现、成本审计、命题证明或反例。
C：冻结任务族划分、3 个模型配置、主实验与消融。
D：外部任务、无变化与不可识别负例、失败审计、论文与复现包。

建议代码目录：envs/、drift/、evidence/、belief/、scheduler/、baselines/、evaluation/、configs/、artifacts/。首篇不构建前端、向量平台或多代理编排系统。

## 11. 论文证据清单

必须形成：问题反例；最近方法边界；明确的新调度机制；至少两种可执行环境；外部迁移；理论或结构性分析；完整成本；负例；复现材料。

建议主图：动机图、架构图、成本前沿、任务复用×漂移交互、消融、无变化/不可识别边界。摘要写结果时只填真实测量，不使用预期数字。
