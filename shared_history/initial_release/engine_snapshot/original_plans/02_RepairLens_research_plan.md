# RepairLens：不完整依赖记录下的修复决策驱动主动重放

版本：研究设计 v1.0｜文献复核截至：2026-09-12

状态：拟研究方案。尚无实现、实验结果或已证明的新定理；数值为建议配置，不是录用保证。

## 1. 一句话选题

当一条已确认错误的记忆或工具输出被纠正后，系统不知道哪些后续产物实际依赖它。通过少量隔离重放，确定一个可靠、接近最低成本的修复方案，而不必恢复完整因果图或重算全部历史。

英文暂定标题：RepairLens: Repair-Decision-Driven Replay under Incomplete Agent Provenance.

## 2. 为什么这不是“再做一次反事实归因”

REVISE 已处理在线修订，并在依赖不完整时保守扩大恢复范围；依赖驱动回滚修复已处理派生记忆；CAR 已通过真实重放估计因果影响；MRFR 已寻找最小修复集合族；Repair or Resample 已强调固定前缀才能区分因果修复和随机恢复。

拟研究的对象不是“到底是谁造成失败”，而是“继续调查是否会改变应执行的修复”。不同依赖解释可能支持同一便宜修复，此时区分它们没有价值。

理论谱系包括 Equivalence Class Determination / Decision Region Determination。不能将“只识别与决策相关的假设”本身声称为新概念。新增难点是部分依赖、随机重放、诊断成本、修复成本，以及诊断重放产物能否被最终修复安全复用。

## 3. 场景与边界

主场景：本地报告生成、数据处理、API 工作流、文件和数据库操作。先单代理、顺序执行；之后才扩展多代理。没有必要一开始支持并发和全部外部副作用。

已知条件：失败日志、已定位的错误源、可靠的新源值或公开的纠正信息。
未知条件：隐含影响路径、哪些已生成摘要/文件需要重算、是否存在替代独立支持。
禁止：向算法提供干净轨迹、标准中间答案、完整真实依赖图、隐藏评测器输出。

不声称精确机器遗忘、与“从未见过旧信息”逐 token 等价、任意真实外部动作都可撤回。目标为声明的功能、状态和后续行为要求。

## 4. 科学假设

H1：当多个依赖模型对应相同低成本修复时，修复决策驱动诊断比全图恢复或全局归因使用更少重放。
H2：依赖记录越不完整，传统图驱动修复越容易漏修或保守重算；主动证据可在部分可识别情况下改善二者权衡。
H3：相同失败前缀、相同总预算下，收益来自探测选择，而不只是获得更多重新采样机会。
H4：诊断中产生的有效重算产物可以复用，但必须满足版本/输入/范围检查；收益需扣除验证和管理成本。
H5：存在不可识别设置，必须保守恢复；不能承诺普遍优于全重启。

## 5. 正式对象

仅有候选依赖图不足以预测干预。每个候选 h 必须包含依赖关系、局部行为约束以及对候选重放结果的预测模型。

H_t：与现有日志及已执行干预相容的依赖—行为模型集合。
R：预先声明或由共同候选生成器提出的有限修复集合。
V_h(r)：修复 r 在模型 h 中是否满足恢复要求。
c(r)：修复成本。首先分析固定确定性成本；实践中使用测量/估计成本并报告误差。

r*(h) = argmin_{r in R: V_h(r)=1} c(r).

robust(H) = argmin_{r in R: all h in H, V_h(r)=1} c(r).

有多个最优修复时，不强行将其当成互斥类别。停止规则是存在一个对所有保留模型均有效、并且在每个模型中均 epsilon-近优的修复：

exists r, forall h in H_t:
V_h(r)=1 and c(r) <= c(r*(h)) + epsilon.

最优性仅相对于声明的候选修复集合，不是所有可能程序/所有修复的全局最优。

## 6. 算法

### 6.1 可实现的第一版

把日志转换成具有稳定 ID 的原子产物：工具结果、结构化主张、摘要、计划、文件变化、数据库写入。保留时间与可观察读写信息；显式数据流是确切边，内容可能影响是待定边。不能将“没有声明边”解释为“不依赖”。

在小型工作流上，每条缺失候选边/前提对应有限备选，包含冗余支持和联合依赖。先显式枚举少量模型，验证原理。较大实例使用受约束候选集合或 SAT/SMT 表示；具体工具选型不是论文创新。

模型可用 LLM 提出，但不能因为模型自报高置信就移除所有其他假设。受控理论轨采用包含真实模型的有限族；实践轨报告候选覆盖误差和保守回退，不声称无条件保证。

### 6.2 候选修复

每次仅考虑有限策略，如重算一个局部组件及其必要前驱、重算两个交互组件、重算受影响后缀、完整重启。每个候选包含输入版本、重放顺序、保留产物、无效化清单、验证要求。

不是盲目枚举所有步骤的所有子集。候选族限制必须显式报告；复杂度结论只在此范围内成立。

### 6.3 诊断选择

定义保守代价差：
G(H) = cost(robust(H)) - min_{h in H} cost(r*(h)).

在模型集合正确且候选修复始终存在时，G>=0。G<=epsilon 是上述停止规则的充分条件（但不是必要条件）。

对可执行探测 u，比较其预期 G 下降与真实重放成本；用小深度规划处理多个探测互补的情况。基线使用随机、逐节点、最大熵和 EC2/DRD 型选择。若使用 G 比值贪心，只把它称作启发式；不能自动继承次模近似界。

探测例子：固定干净前缀、替换已确认纠正的源，再重新计算一个摘要或子流程；比较结构化结果、公开约束和状态变化。不能用 LLM 预测整个后续轨迹替代实际重放作为主实验。

### 6.4 生产性重放与成本

诊断可能已经计算出正确产物。仅在前提版本、状态快照和验证契约一致时，将它放入可复用产物池。

目标成本：所有诊断重放 + 最终未完成修复 + 校验/状态管理。已经执行的同一次计算只计费一次；不得既计算“信息增益”又把同一收益重复扣成本。

### 6.5 随机性处理

固定前缀的模型和工具结果、核对请求哈希、恢复相关环境状态；从干预边界起重新运行。相同 seed 不等于远程模型输出保证一致。

确定性机制层可以准确比较；随机模型层重复采样，估计恢复概率和状态错误概率。若根据中间结果自适应停止，采用适用条件下的 confidence sequences / error spending，或者使用独立最终认证样本。普通固定样本 CI 不能无限窥视后择时停止。

## 7. 理论计划

基础：只要真实依赖—行为模型 h* 位于 H，且 r 对 H 中全部模型有效，则 r 对 h* 有效。这是直接逻辑结论，不能当作主要新定理。

研究目标一：构造图复杂度增长但修复决策类不增长的模型族，比较完整图识别与修复确定的查询复杂度，给出上下界或明确分离。区分对数级信息下界与具体可用探测的可达上界，不能仅按类别数量就声称只需 log K 次。

研究目标二：构造观测等价但修复要求冲突的模型，证明在声明的干预集合下不存在同时可靠和局部的恢复策略，必须增加观测或保守重算。

研究目标三：分析诊断和修复共享计算产物后的成本，不沿用“诊断实验全部作废”的传统成本。首先精确求小问题动态规划，再分析近似策略；若假设不满足，不声称 near-optimal。

随机扩展中，若能分别控制候选漏真、重放不忠实和验证错误，可给条件性风险分解；这些误差项必须实际估计，不能假定为零。

## 8. 数据与信息协议

### 8.1 机制集

拟 200 个独立工作流，每个 10–40 个产物节点；80 开发、40 校准、80 测试。按图模板和生成机制划分，禁止同模板换 seed 后分到训练/测试两边。

包含：单源传播、联合影响、替代独立支持、相同观测不同结构、多个结构同一修复、无法被允许探测区分的情况。

### 8.2 真实执行扩展

从 AppWorld 或本地工程任务获得真实代理轨迹；对已验证成功的前缀插入公开定义的错误类型，再实际继续执行以形成失败，不伪造纯文本失败日志。进入比较的各方法从同一个失败快照出发。

依赖缺失分两种：随机删除（诊断）与结构性遗漏（主设置），例如摘要来源丢失、跨任务引用未标注、先写入文件后从文件读取等。删除率可设 0%、20%、50%、80%，但率本身不是现实分布估计。

另外收集至少 40–60 个未经人工注入的自然失败案例，独立人工检查失败源；若数量不足，报告真实数量，不用合成案例填补“自然失败”。自然失败子集是条件性恢复评测，另报未筛选任务端到端结果。

### 8.3 验证器隔离

代理可使用公开接口文档、用户要求、类型和运行检查。最终隐藏测试、标准中间状态、真实影响图只由评测器使用，不能参与搜索、停止、挑选修复或模型提示。

后续错误复发由隐藏 follow-up 任务测量：这些任务在修复结束后才运行，不得作为优化反馈。

## 9. 基线与消融

基线：原地继续；完整重启；最早冲突起后缀重算；REVISE 式保守依赖恢复；已知错误源下的图级联修复；逐节点/逐项删除重放；CAR 归因加共同修复器；固定候选上的联合重放；最大熵；EC2/DRD 型调度。

为隔离贡献，共享候选修复器、可用探测器、模型、失败起点、总预算和验证器。将各系统原生端到端对比与共享模块的机制对比分开报告。

消融：去掉决策停止；将修复目标换成全图识别；不复用诊断产物；删除联合依赖；把待定边当不存在；使用完整图上界；不固定前缀的“错误评测对照”；固定点估计代替随机重复的敏感性分析。

## 10. 结果指标

主图：完整恢复率—端到端成本前沿。

完整恢复 = 当前任务结果符合要求 + 声明的持久状态要求通过 + 预注册后续任务不复发。不要要求自然语言摘要与全重启结果字节一致；使用语义/结构化不变量。

另报漏修、无关状态破坏、重放次数、实际重新计算的节点/token、诊断开销、回退比例、图恢复率（辅助）、失败机制是否消除、候选覆盖率、最终认证误差。

“最终回答正确”不能替代完整恢复；“保留节点多”不能替代保留的节点有效。

## 11. 统计与止损

任务/原始失败轨迹为配对统计单位。多次重放属于同一簇；不把它们当独立任务扩大 n。以独立 pilot 的方差确定正式样本量，并冻结主假设、预算、阈值。

建议继续投入门槛：相对完整重启或最强等信息恢复策略，完整恢复率满足预定非劣边界（例如 -2 个百分点），同时总重算成本下降约 25%；或固定成本下明显提高完整恢复率。数字不是发表统一要求，应结合 CI、任务难度、外部有效性解释。

止损：诊断比重启贵；只有获得完整干净轨迹才能成功；随机重放同样有效；收益只存在随机删边、不存在结构性遗漏；回答改对但后续仍复发；理论需要的候选覆盖在现实中无法维持。

## 12. 实现与阶段交付

模块：recorder/（日志与边界）、snapshot/（文件和数据库）、hypotheses/（模型族）、repairs/（候选策略）、probes/（实际干预）、scheduler/（决策差优化）、certification/（公开检查与随机统计）、evaluation/（隐藏评测独立进程）。

A：记录与重放忠实性验证；小型生成器；全重启和后缀基线。
B：有限模型精确解；共同修复器；主动调度；不可识别反例。
C：结构性依赖遗漏、随机模型重复、完整恢复和成本统计。
D：外部/自然失败、消融、失败审计、论文与复现包。

第一阶段最重要的验收不是“成功恢复一个任务”，而是相同前缀可以真实重建，且结果差异不会由偷偷重采样前缀造成。

## 13. 论文主张

主张 A：完整归因不是作出正确修复的必要条件。
主张 B：与修复选择无关的诊断可以被跳过；收益取决于结构不确定性与决策不确定性的分离。
主张 C：在部分可识别、可重放的真实任务上，完整恢复—成本前沿得到改善，而不是单纯回答准确率改善。

潜在投稿取向：偏 Agent/NLP 的算法与行为分析论文，或偏软件工程的执行可靠性论文；具体会议要在主要证据形成后按 scope 选择，不承诺录用。
