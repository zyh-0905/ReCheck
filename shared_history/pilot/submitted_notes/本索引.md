## 三句话结论

1. **执行干净**：294 次真实调用、**0 次 HTTP 失败、0 次截断**、128/128 + 12/12 记录完整，独立审核**硬失败 0、警告 0**。
2. **正确率差异不是调度造成的**：ReCheck 的两个错误经逐行核对**都是模型自身执行错误**（一例用错除数、一例违反输出 schema），而非缓存失效；128 行里"语义陈旧"只出现 1 次且那行答对了。
3. **本轮测不出算法优劣**：`recheck` 与 `myopic` 的探针决策 **32/32 逐位相同**（价格与权重对称导致 DP 退化为 myopic），且目标失效模式**未被复现**。这些是阴性结果，按协议保留。

## 需要你注意的三件事

1. **模型 ID 写法**：`deepseek-v4.1-flash` 在端点上不存在，会直接报错。本实验请求的是 `deepseek-flash`（= V4.1-Flash）。如果你必须要求日志出现 `v4.1` 字样，需要另找端点。
2. **作废批次保留未删**：`运行摘要/recheck_作废_4096截断/` 记录了 4096 输出上限导致的截断（模型把 4096 token 全烧在思考上、`content` 为空）。正式运行改用 16384 后，单次思考最多用到 **8140** token —— 说明这个决定是必要的。该目录已不可续跑。
3. **RepairLens 预检的边界**：依赖规则是**明写在任务文本里**的，模型不需要从修复历史学习依赖图。因此**不得**据此声称 RepairLens 有效或优于其他方法。

## 如何自行复核

```bash
# 校验上传包内每个文件的 SHA-256
python3 -c "
import json,zipfile,hashlib,sys
z=sys.argv[1]
with zipfile.ZipFile(z) as f:
    m=json.loads(f.read('EXPORT_MANIFEST.json'))
    bad=[r for r,h in m['sha256'].items() if hashlib.sha256(f.read(r)).hexdigest()!=h]
    print(z,'mismatches:',len(bad))" 上传包/recheck_deepseek_v41_flash_cap16384.zip
```
