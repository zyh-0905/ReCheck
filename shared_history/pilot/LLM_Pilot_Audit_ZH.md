## 4. ReCheck：成绩正确，关键归因错误

| 方法 | 正确/任务 | 正确率 | 运行期探测数 | 过期且相关的记忆暴露 | 相应错误 |
|---|---:|---:|---:|---:|---:|
| ReCheck | 32/32 | 100% | 20 | 0 | 0 |
| Myopic | 32/32 | 100% | 20 | 0 | 0 |
| TTL | 31/32 | 96.875% | 16 | 1 | 1 |
| Always | 31/32 | 96.875% | 64 | 0 | 0；另有1次接口违约 |

运行期探测数不包含四个共同初始前缀的8次校准探测。代理探测价格 0.18 是模型中的代理成本，不是美元，也不是实际 API 费用。

### 4.1 必须撤回“TTL 是模型除错数”

原始记录：`records/rc_001_001_ttl.json`。核对原始请求而不只看报告，得到：

| 字段 | 原始值 |
|---|---|
| `worker_view.memory.amount_divisor` | **100** |
| `probed_channels` | `[]` |
| `plan.amount_divisor` | **100** |
| `tool_result.sum_amount_raw` | **1023.35** |
| `answer.total` | **10.2335** |
| 私有环境当前金额模式 | 0，即正确除数 **1** |
| 正确总金额 | **1023.35** |

模型计算 `1023.35 / 100 = 10.2335`，与给它的旧记忆和执行计划一致。错误是旧语义未刷新后被传入工作模型，不是模型把一个正确的除数1擅自改成100。

同一流同一任务中，ReCheck 和 Myopic 先取得金额校准收据，把记忆改为1，随后模型返回1023.35。这是一个清晰的机制个案，但不是基于大量独立样本的因果效应估计。

**正确归因：1次过期记忆传播错误＋1次模型接口契约错误。**

直接对应的原始调用：

- TTL plan: `calls/92082c72e2a3891c5d22c1680b53ee6f61a03f5e716f7208c9d8133553dfbf0d.json`
- TTL answer: `calls/afe77c4a929fe75ea47ad3ff18865022b5ccf2a73b40d70a1f91b88bd128025a.json`
- ReCheck plan: `calls/3897bc8024da28e2f50f1f0344bdd0d4487d4fbd67f75c8407997831b4e4892e.json`
- ReCheck answer: `calls/7b38d8c4ee8ab408222c38687e7536e4df13be0952e096810f9ba2655aa55590.json`

### 4.2 已定位附带审核脚本的问题

脚本用 `amount_divisor in (1,100)` 和 `isinstance(endpoint_inclusive,bool)` 判断语义是否“known”，继而将“known却答错”归入模型错误。这只能判断值是否存在、类型是否合法，不能判断它是否与当前环境一致。

正确的离线审查至少区分：缺失／非法；存在但已过期；与当前语义一致。金额应与当前真值映射得到的1或100比较，端点应与当前模式比较，且只对本任务实际依赖的通道计相关失效。这些真值比较只能由离线评测执行，不能提供给在线策略。

脚本没有实际实现报告声称的“新鲜性逐例核查”。“硬失败0、警告0”不能扩展解释为研究归因正确。

### 4.3 Always 的错误归因成立，但它不是 JSON 语法错误

`records/rc_002_004_always.json` 为只需要 count 的任务。模型给出了 `amount_divisor=1`，而协议要求不用的字段为 null。工具据此拒绝执行，模型最终按错误处理指令返回两个 null。

这说明刷新全部证据不能避免接口错误。应报告接口失败与记忆失败两类，不应据一次失败证明 Always 在总体上更差。

### 4.4 ReCheck 与 Myopic 完全相同的范围，比报告写得更强

32/32 配对任务的年龄、探测选择、worker_view、plan、answer 全部相同；对应64/64模型请求正文也逐对象一致。请求ID独立，原代码没有在这两种方法之间共享最终答案。

因此该运行中没有在 LLM 输入层施加不同处理。两者费用和耗时的差异不能归因为调度改进；没有固定思考强度参数，也没有独立重复来估计服务随机性。即使最终答案相同，内部生成长度仍可不同。

### 4.5 不能归结为“对称价格必然退化”，也不能仅延长步数

离线枚举原版模型的可达年龄表明，原价格(0.18,0.18)下，H=8、20、40都没有DP与Myopic决策差异。仅把8步改成20或40并不能解决这组设置的问题。

反例：保持两通道仍然对称，仅令价格为(0.22,0.22)，在剩余2步、年龄2、任务类型0、金额通道上，DP选择刷新而Myopic不刷新。其他权重、转移和危险率不变。

该反例只说明“不对称是必要条件”不成立，不是新方法胜出的实验。下一轮应先离线检查策略是否可区分，并在预设参数范围内包含等价区和不等价区；不能看到某个随机种子有利后再选它做测试。

### 4.6 目标机制不是完全没出现，而是只出现一次

四条独立流中，两条设计为 no_drift，两条允许变化；本次实现的变化都发生在流1，金额与时间端点各变一次，流3没有实际翻转。整组只有1个“相关记忆已过期”的任务—策略记录，正是失败TTL。

因此应写成“观察到一个过期记忆传播个案，但暴露不足以比较总体优劣”，而不是“目标失效模式未复现”。

## 5. RepairLens readiness：少调用不等于省钱或省时

| 方法 | 成功 | 修复阶段调用 | 输出tokens | 配置高峰估价USD | 调用延迟合计s |
|---|---:|---:|---:|---:|---:|
| 全量重生成 | 4/4 | 12 | 860 | 0.0017298 | 12.7350 |
| LLM选择局部修改 | 4/4 | 10 | 2446 | 0.0038466 | 17.0184 |
| 保留旧状态 | 1/4 | 0 | 0 | 0 | 0 |

选择局部修改比全量重生成少16.7%调用，但模型调用费用高122.4%，调用延迟高33.6%。峰谷费率按相同比例缩放，不改变这两个方法的费用比值。这里是记录的调用延迟合计，不含全部运行间隔、完整机器占用和其他未计时开销。

四次选择调用共花0.0029775 USD（原配置估价），已经超过12次全量生成的0.0017298 USD。问题不是选择错了，而是选择成本高于节省的重算成本。

四个选择集与本数据的受影响产物完全一致。案例3仍发生 tariff 数值修订，但三个产物均只依赖 archive_allowance，所以是“修订对这些产物没有影响”，不是源值完全没改。

这些数据证明这个简单显式规则环境中的固定前缀与局部修改流程可以运行，并暴露成本问题。它没有执行RepairLens主动假设调度器，不能用于声称RepairLens优于全重启；规格文本明确给出依赖，普通规格解析就是必须比较的简单基线。

建议的盈亏分析：如果每个产物重算成本相近为c，候选总数N、需改K个，选择成本s，则局部策略需要满足 `s < (N-K)c` 才可能降低费用。真实策略应根据可获得的成本估计，在选择、批量生成与直接重算之间决策，并保留真实低成本负例，不能人工sleep后宣称加速。

## 8. 下一阶段研究门槛

1. 修正离线新鲜性归因，给本次TTL样例增加回归测试；把类型合法、信息新鲜、接口有效、答案正确分开。
2. 在任何新付费实验前，离线验证DP/Myopic确有机会产生不同的公开输入。原版0.18价格单纯延长到40步仍不够。
3. 预先声明漂移、复用和价格范围，包含对照负例，不因方法是否胜出筛选测试种子；使用新开发批次和独立测试任务族。
4. 增加不刷新/规范执行等诊断对照，测量基础失效机会；保持模型、探测能力、共同前缀及账单口径一致。
5. 对RepairLens先研究真实选择成本与剩余重算成本，再接入主动调度。不要将预检选择器改名，也不要移除任务必要规则来人为制造不可解题目。
6. 从四条流/四个案例不能建立显著性和泛化结论。可先补足成本和失败机制，不必立即购置算力或大规模重跑。

## 9. 可写入与不可写入的论文结论

**可以写：**单模型受控预实验的实际调用与token量；有记录支撑的一个TTL过期语义传播失败；一个Always接口失败；ReCheck与Myopic在本配置下相同；局部选择虽减少调用但本轮费用和延迟更高。
