# Development diagnostic: autonomous target resolution on native tools

**Evidence status.** Audited R7C1 (`r7c-1.0.1`), not a confirmatory efficacy trial or an official ToolSandbox benchmark score. No new model responses were generated during this audit. These results do not constitute evidence for RepairLens.

We evaluated an autonomous JSON-action agent on 14 constructed scenarios using pinned, native ToolSandbox contact, messaging, and reminder tools. The scenarios share three intent templates and two tool domains. Each scenario was run under three prompting conditions: removal of all pre-task memory and observations (Stateless), provision of inherited evidence (Inherited), and the same evidence plus a generic pre-write target-resolution instruction (Resolve-rule). Each episode was limited to eight model requests. Six additional episodes independently repeated two prespecified cases; repeat outcomes were not substituted for primary outcomes.

All three conditions safely completed 14/14 primary episodes, with no observed unauthorized writes, and all explicitly terminated. The six repeat episodes also completed safely. Primary model-request counts were 51, 49, and 49, while native tool-call counts were 37, 35, and 35, respectively. In all 27 primary person- or description-targeted episodes, the agent queried the current target before the consequential write, including in the Inherited condition. In all 15 literal-phone-number episodes, the agent followed the specified number rather than resolving it to another contact. The six primary episodes with disabled cellular service checked and enabled the service before sending; none elicited an actual native tool exception. The experiment therefore does not demonstrate error-triggered recovery.

This is a ceiling result for the present diagnostic: the additional resolution instruction produced no observed gain in final task correctness. It does not establish equivalence, universal safety, or the absence of stale-memory problems. The shared base instruction already warned that historical evidence could be outdated, and the user requests explicitly specified current identities or literal numbers. Native scripts that blindly reused stale bindings previously exposed failures; those script failures cannot be imputed to the autonomous model, which actively reacquired evidence here. No held-out task-family transfer or known failure requiring a more complex ReCheck controller has yet been established.

The original repeat statistic compared complete action objects, including the free-text terminal `done` message, and consequently marked all six pairs different. Separating operation from wording yields three pairs with identical tool names and arguments and three with operation differences, mainly optional cellular checks or post-write verification. All six pairs retained the same target outcomes. The repeat design fixes only initial state and messages; later contexts can differ because of tool choices and generated UUIDs or timestamps.

Costs were retained rather than inferred from request counts. The 149 primary requests consumed 285,995 input and 12,039 output tokens; 19 repeat requests consumed 36,407 input and 1,648 output tokens. Including one smoke request gives 169 requests, 322,450 input tokens, and 13,710 output tokens. Reasoning tokens are included in output counts. Recorded model-call latency was 186.893 seconds in total; the main run's 270.525-second wall time also contains waiting and local execution. Currency costs remain unknown. The requested model label was `deepseek-v4-flash`, and every recorded response used `deepseek-flash` with the same fingerprint. These fields identify the recorded metadata cohort, not independently authenticated weights.

**Placement.** Use as a development/negative-result appendix or claims-to-evidence discussion, not as proof of a new controller's superiority. The 42 primary method-case episodes are not 42 independent task-family samples. The evaluation score is goal achievement without wrong writes; explicit termination was measured separately and happened in every episode.
