## 2. 执行发现及其边界

上游函数在手机联网时，搜索指定号码对应的联系人。如果没有找到联系人，仍写入消息，recipient_person_id为None；若旧号码已分配给其他人，则写入其他人的ID。返回值只有message_id。

源函数体测试覆盖：

| 情形 | 受控测试中观察 |
|---|---|
| 联系人号码没有变化 | 旧号码发送到目标 |
| 只有无关联系人变化 | 目标仍正确 |
| 目标改号，旧号码没有匹配联系人 | 仍返回消息ID，但收件人ID为None |
| 目标改号，旧号码分配给他人 | 仍返回消息ID，但收件人是他人 |
| 先查询目标当前号码再发送 | 在相同测试替身中写入目标当前号码 |
| 蜂窝状态关闭 | 显式抛ConnectionError，写入前失败 |
| 失败后恢复蜂窝再重试 | 测试中仅产生一次消息写入 |
| 写入后查询目标 | 能发现当前号码，但不会撤销之前的错误写入 |

结果文件有8个固定契约fixture加17项单元测试。它们是源程序反例验证，不能报告为代理成功率、外部任务成绩或统计独立样本。

同一固定UUID/时钟是测试耦合手段，用于展示响应不依赖目标身份；不是声称真实系统每次返回同一UUID。完整调用轨迹、存储状态可能区分两个世界，不能把“即时返回不够”扩大为“任何后续查询都不够”。

**有限结论：工具调用成功不自动证明动作目标正确；显式错误恢复与静默错误预防需要分开测试。**先查联系人是很强的简单对照，不能把它重命名为新算法。

## 3. 一个基础信息边界，不是新定理

设两个状态的可见旧记忆相同：目标当前号码分别为p0和p1。若执行前不获得新信息，且必须从两个号码中选择一个，两个状态等概率时任意随机选择的错误率均为1/2：

`0.5*(1-p) + 0.5*p = 0.5`。

Fraction枚举101个有理随机概率验证了等式。一般证明由上述一行等式给出。这个构造仅解释为什么单纯反思或观察发送成功不能替代新的身份信息，不是新颖性或真实错误率估计。允许弃权能降低错误发送，但须同时计算任务完成率。

## 4. 实际阻断与不能混淆的能力

`verification/clone.log`和`verification/dependencies.log`保存实际失败信息：git/pip直接访问失败，不能解析目标网络地址。本次本机包探测另记在environment.json；Polars未安装。GitHub连接器能返回源文本，但不能通过该读取接口把PyPI二进制扩展安装进运行容器。这是源阅读与执行环境下载通道不同，不是拒绝继续实验的理由。

原依赖ccy1.3.1声明Python>=3.8,<3.12，因此材料请求固定为Linux x86_64 CPython3.11，而不是强行在当前3.13解释器上修改上游。运行时下载自公开python-build-standalone指定资产，SHA256已从官方发布页读取。其他包选固定版本的PyPI发布元数据和兼容wheel，保存每份元数据并核对其SHA256；这不是所有依赖摘要都事先已知的完整复现锁文件。

材料集用于本地工具、状态、评测与基础测试；未下载全部云提供商/模型角色栈，也不声称安装后的所有上游命令必然一次成功。后续由研究端在隔离目录安装、继续定位兼容问题。不会因此要求用户跑离线算法。
