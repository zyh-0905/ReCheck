# 研究协作与每轮放行机制

## 分工

| 工作 | 研究审核者（本对话） | 执行者（用户及本地代码助手） |
|---|---|---|
| 研究问题、相关工作、基线、理论 | 负责设计与修订 | 不自行改变主张 |
| 代码和实验协议 | 给出有版本的可运行任务包、输入、上限与停止条件 | 运行固定版本；异常回传 |
| API密钥与运行机器 | 不索取密钥、不声称能直接控制用户机器 | 本地保管与授权，执行付费调用 |
| 原始数据 | 设计完整日志与审核方法 | 保留全部尝试、错误、中断、成功记录 |
| 复算、错误归因、统计 | 复核后明确可用范围和问题 | 不替模型补答案，不只报优胜结果 |
| 下一轮是否执行 | 按证据给出明确范围；不确定项如实标注 | 没有新任务包或明确运行边界，不自行扩大 |
| 论文、图表、LaTeX | 根据已核验的数据更新 | 最终作者人工审阅和确认 |

这是一种逐轮协作，不是后台运行承诺。收到实际反馈时完成相应审核。助手审核不等于独立同行审稿，也不保证会议录用。

## 每轮固定交付

研究审核者给出：任务ID、要回答的问题、冻结代码/配置、执行prompt、具体命令、预计调用数量与硬停止条件、回传文件定义、可支持/不可支持的论文结论。

执行者回传：原始请求响应、全部attempt、环境/版本、任务数据、错误和中断、真实token/计时、已知费用及缺失项，以及任何偏离协议的说明。密钥不离开执行机器。

## 审核分层

1. **软件与记录层**：路径、代码、配置、请求、响应、重试、前缀、哈希是否相容？
2. **实验设计层**：实际输入是否有区分度，预算是否对齐，标签是否泄露，模型和测试是否冻结？
3. **结论层**：失败归因是否正确，成本是否含诊断，单位与分母是否正确，小样本是否被夸大？
4. **论文层**：哪些数字可以进入哪一节，哪些只能称开发预实验，哪些需要更新或撤回？

## 审核结论与动作

| 结论 | 动作 |
|---|---|
| 通过，可推进指定下一阶段 | 发布新的任务包；不自动开放无限预算 |
| 条件接受 | 保留数据，明确局限；只补所缺诊断，不全量重跑 |
| 记录/代码/协议错误，需要重跑部分 | 说明受影响范围、新版本和新目录；原批次留档 |
| 方法无收益或出现负面结果 | 先修订假设或停止方向，不以重复随机采样追求显著 |
| 证据无法恢复 | 标为不可核验，不生成“替代历史”；新实验单独记录 |

没有明显增益不等于实验不合规。通过不是指新方法必须获胜。
