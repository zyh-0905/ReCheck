# 实现审查与能力边界
这是同一助手的代码审查与自动测试，不是独立人类或独立模型审稿。
审查点：
- 没有content动作解析器；旧多对象响应只作为不合格结束文本，不执行任一片段。
- 所有函数参数先完整JSON解析与本地schema检查，再调未改native bridge；名称白名单。
- 同条响应的全部原生调用先验证，之后按返回顺序执行，不丢掉后续调用、不并行。
- 真实工具结果只能由NativeSession产生并以对应tool_call_id写入role=tool；保留assistant的reasoning_content。
- token/原始bytes/身份字段/partial与资格结果分离；缺失响应不假定未收费。
- 无自动重试与恢复，无smoke补齐，成功/不合格均不能重新采样。
- 校验当前3个预设资格目标的状态，不把它作为原R9评分；外部事件禁用。
- 原生读写不连接真实账户；网络阻止仅覆盖Python连接入口，非操作系统安全证明。
- 测试客户端只接回环或注入固定响应。live CLI没有可切换模型、预算、测试端点的参数。
- 源/数据一并冻结；运行结果导出白名单不扫旧目录。
未完成：远端native接口兼容性、跨平台实机执行、新LLM研究任务、一般安全、发表证据。
依赖沿用旧固定版本是复现选择，不是当前安全版本推荐；执行应限隔离的模拟数据。
