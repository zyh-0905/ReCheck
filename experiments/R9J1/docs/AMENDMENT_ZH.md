# R9J1：JSON 输出契约修订

版本 r9-1.0.1；协议 R9J1_LIVE_CONTINUATION_DIAGNOSIS_01。
该修订是在查看旧R9第一次主响应之后提出的，属于事后披露的协议变更，不是外部预注册或算法贡献。

## 原始证据
旧协议只有2份响应：1次smoke正常结束，1次主请求返回“两个JSON对象与中间散文”。主请求身份及usage一致、finish_reason=stop，但不是一个合法JSON文档。
解析发生在执行工具之前。因此没有执行消息发送、没有执行模型写出的查询、没有触发状态事件；0/32主回合和0/4重复回合完成。
这个输出是旧设置下真实的格式不合规记录，不能删除、改成成功、截取其中一个动作或认定“模型按其动作正确完成”。主任务成功率未定义，不按0%或100%填写。

## 唯一推理行为变更
所有smoke和主请求新增顶层参数：

```json
{"response_format":{"type":"json_object"}}
```

该字段在config.extra_body中冻结，经原request_payload展开进入顶层请求体。
模型、地址、输出上限16384、thinking enabled、reasoning_effort high、任务、系统提示、工具权限、状态事件、评分及10轮上限均不变。
接口支持结构化语法约束会改变输出条件，因此新结果必须标注R9J1/JSON mode，不能与旧R9称作完全相同的生成条件，也不能把新的较好输出用于抹去原失败。
这不是新算法，不引入更长的任务提示，不加入第二次修复模型，不用原生tools或json_schema，不增大输出上限，不降低推理强度。

## 保持严格执行
客户端仍只接受一份无重复键、无非有限数字的JSON对象。多对象、散文、空内容、围栏、截断一律保留并暂停；不抽取首对象，不拼接或自动修复，不重试到成功。
合法JSON不等于正确动作。动作结构/工具参数错误仍在原定回合中返回模型，安全评分不变。
HTTP、usage、返回标签及指纹门槛不变。JSON Output并非业务schema保证；官方文档提示可能空content，因此仍须实际smoke确认。
smoke只有接口检查意义，不能保证复杂任务必然符合格式。

## 数据与预算
旧目录保留paused。R9J1在全新根目录建立smoke和主run，不导入旧smoke或旧响应为完成任务。
新修订最多1次smoke+360次主请求=361次。旧R9已记录2次，沿革累计上限363次，比原361多出2次检查/首响应。旧响应的2678输入、154输出、2832总token保留；费用UNKNOWN。
32个主回合、4个重复回合不变。新run首任务仍为primary_n06_verify_confirm，不按旧输出选择另一个顺序，不增加案例。
再次出现格式问题时只导出，不额外启用模型、/models探针或账户查询，不修改策略以强制获得更好结果。

## 当前验证性质
研究端只执行原始响应的离线重放和本地HTTP测试；不宣称JSON模式的真实端点效果已经得到验证。元数据一致性不是权重认证。
修订安装/准备不是新的科研结果。旧输入包不变，R8论文主表不变，RepairLens没有新证据。
