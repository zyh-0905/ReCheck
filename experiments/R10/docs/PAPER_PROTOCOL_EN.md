# Prospective R10 diagnostic protocol (not a result section)

R9NT1 revealed an operation/intent mismatch: three failed primary episodes contained actual post-write reads, yet the reads did not establish that the mutated object still satisfied the user's selection criterion. In reminder cases, resending old optional fields also overwrote a concurrent content change. That observation motivates a bounded 2×2 diagnostic, not a new concurrency algorithm.

R10 uses file-backed SQLite and two real connections for a single cooperating event schedule. The two task families are a service-to-configuration join and ranked selection among eligible dispatch batches. Twelve constructed cells contain stable and irrelevant updates, a protected-field update, a selection-only update, and literal-identifier controls. They are not twelve independently sampled real-world tasks, and the two families are not independent public datasets. The same seven API schemas are offered in all four arms: six database functions and a non-authoritative completion-report function. Optional row-version and selection-token checks are standard, same-capability baselines. Their checks and writes execute in a target-local SQLite transaction; no claim is made about remote atomicity.

The guidance factors are minimal business-field submission and target resolution anchored to the original user criterion. The base arm may freely use these behaviors and the same conditional writes; it is not forced to resend stale records. All arms already receive preservation instructions and a caution about historical evidence. Additional guidance changes prompt length without a matched placebo. One model endpoint/profile is used. Forty-eight primary episodes have an eight-request cap, with no best-of-k or repeat replacement. Paid-model outcomes have not yet been collected.

We predefine distinct outputs for target achievement, final-state conformance, trace-safe completion, conditional rejection, reported completion, and false completion claims. A missing report does not count as an accurate report. Evaluation uses full offline states, but the acting agent sees only the user request, prior legitimate observation, documentation and results of its own tools. Event exposure is endogenous to querying and is reported separately; all assigned cells remain in the main denominator. Actual tokens, request counts and tools are measured separately and are not converted into unknown currency.

The accompanying 96 *scripted* runs test executable mechanism coverage. They deliberately compare fixed write/verification contracts and must not be reported as model behavior. Their small deterministic counts are not estimates of deployment error rates. Both re-resolution and complete conditional checks are strong simple controls, not our proposed inventions.
