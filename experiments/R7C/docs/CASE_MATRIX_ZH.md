# 情形定义与纳入边界

4个目标家族、每家族6个固定情形；不是24个独立官方场景。
目标家族在查看真实模型响应前选定，不根据方法胜负选择。
所有初始旧记忆来自真实原生查询。多个方法复制同一状态快照；fixture ID不进入模型提示。

|目标家族|稳定|无关变化|相关变化|变化后观察|变化前观察|明确异常|
|---|---|---|---|---|---|---|
|c00–c05 人物消息|原号不变|无关联系人改号|目标改号且旧号归别人|相关变化后查目标|相关变化前查目标|目标改号转号并关闭蜂窝|
|c06–c11 字面号码消息|同上|同上|同上但用户仍指定旧字面号码|变化后查人物|变化前查人物|转号并关闭蜂窝|
|c12–c17 当前同名提醒|原ID保留|无关联系人改号|原ID变成另一个提醒，新增同名目标|重建目标后查询|重建目标前查询|删除原ID、另建目标，旧ID调用报错|
|c18–c23 Wi-Fi依赖|Wi-Fi关、低电量关|无关联系人改号|低电量打开并关依赖服务|变化后读取Wi-Fi/低电量|变化前读取Wi-Fi/低电量|Wi-Fi已打开，重复开启会报错|

“明确异常”列不声称所有策略都会触发错误：模型可以先查询而避免错误。
Wi-Fi的相关变化是显式状态依赖，不是构造静默误发；字面号码组是意图控制，不故意判为改号错误。
没有观测时和变化前观测时的可見输入相同/相近是有意的部分可观测诊断，不提供当前变化标签。
变化后观察也不附带“绝对新鲜”判定，只显示原生查询结果；本组模型启动后世界不再改变。

冻结输入位于fixtures/cases.json。public projection仅发送task、允许的历史记忆、普通观察、工具文档和已发生的动作历史。
private_goal/snapshot/setup_events/condition只供生成及离线评分，严禁加入模型输入。

这些任务调用ToolSandbox原生工具与状态，但初始资料和任务文本由本研究构造；
没有调用上游Scenario.play、用户模拟器或官方里程碑评分。不将其称为ToolSandbox官方分数。
