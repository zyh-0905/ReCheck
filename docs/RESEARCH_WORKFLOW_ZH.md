# 研究流程、版本和证据定位

## 两条必须分开的流程

**历史模型实验：**研究方案 → 冻结代码/配置/调用上限 → 用户本地调用真实模型 → 保存请求、响应、工具状态和账本 → 用户回传原ZIP → 研究端复算/原生重放 → 审核及单独更正 → 保留结果或决定下一步。

**公开语料审计：**固定数据集提交 → 下载原始JSON并核对摘要 → 按来源模型/人设/trial/任务建立复合身份 → 检查调用与回执、表快照边界 → 保存原指标 → 按明确局部任务规则筛查 → 审阅修订/时区/语义例外 → 数值复核 → 生成论文用描述表。

第二条流程没有重新生成公开数据中的模型答案。复制、重评分、代码复验与新增模型样本不是同一件事。

## 阶段入口规则

`experiments/`保留R2—R10等原运行器；具体子目录以[完整导航](../CONTENTS_ZH.md)为准。`stages/R*/`保存原始交付包、报告、CSV和验证记录；早期目录保留原结构，R12起统一分为reports/results/verification/archives/handoff。

`feedback/*/original_upload/`为原始用户ZIP。`raw`、`readable`等为方便阅读的副本，不是再次运行的结果。反馈19对应R12，反馈20对应R14采集。R7C曾有同名不同规模交付，必须按`history/same_name_releases`以及R7C1协议区分，不混用源码和预算。

`analysis/R12`至`analysis/R16`保留各原包的完整相对路径。原包内的`MANIFEST`继续约束各自原环境；根级`ARCHIVE_MANIFEST.json`约束当前整合归档。旧导航和旧根清单在`history/archive_through_R11`中，不用于验证现在的整合目录。

## 重复、失败与更正

原始失败请求、暂停日志、没有优势的结果都保留。`Factual_Corrections`属于对原报告的补充，不能覆盖原始响应。后续复算一致也不意味着旧文本每句话都正确。

研究端对工具执行的重放，只复用已保存的动作与回执；局部分支不能连成一个未经执行的新Agent策略。本文最新结果以R15和R16的范围说明为准；历史方法收益不能外推到当前诊断研究。
