## 2. 本轮架构变化（由协议规定，非我选择的调参）

LLM 只生成**任务所需的计划字段**；SQLite 真正执行；**数值答案由确定性程序渲染**，没有第二次 LLM 回答调用；初始记忆由两次实际校准探测**确定性解码**（不再由 LLM 学习）；只给模型**当前任务相关**的语义，不给核验时间戳或无关记忆。

因此 **R3 与 R2 的正确率差不能解释为提示优化或模型推理能力提升** —— 架构本身变了。

## 4. 成对处理分析：差异集中在“真正相关”的位置

对 208 个（流×步）成对比较：

| 指标 | 数量 |
|---|---|
| 刷新动作不同（`probe_diff`） | 45 |
| **真正影响所用通道的语义不同**（`relevant_semantic_diff`） | **21** |
| 实际请求体不同（`payload_diff`） | 21 |

即 **45 处动作差异中只有 21 处真正相关** —— 与 R2 的观察一致（动作差异多于语义差异）。

**在这 21 个真正相关的对上**：

| | 数量 |
|---|---|
| recheck 成功 | **12** |
| myopic 成功 | **5** |
| 两者都成功 | 0 |
| 两者都失败 | 4 |
| **仅 recheck 成功** | **12** |
| **仅 myopic 成功** | **5** |

全体 208 对中不一致对共 17 个，**全部 17 个都落在这 21 个相关对里**；两者都不一致的方向为 12:5。由于独立单元只有 16 条流（且相关对高度集中于少数流），**这不足以支持显著性主张** —— 交给研究审核。

## 5. 最重要的机制性发现：错误现在 100% 归因于记忆陈旧

架构改变后，模型侧噪声被消除，正确性完全由记忆新鲜度决定：

| 记忆状态 | 答对 | 答错 |
|---|---|---|
| **陈旧** | 0 | **51** |
| **新鲜** | **333** | 0 |

- **陈旧时错误率 = 1.0000；新鲜时错误率 = 0.0000** —— 完美分离。
- **模型计划忠实于所给证据：384/384**（计划字段完全等于按所给记忆推导的规范计划）。
- **端点换算全部正确**：`time_bound` 与 `(cutoff, endpoint_inclusive)` 一致 **212/212**。
- **接口违规 = 0**（R2 有 4 例）；**`count_before` 语义误加 = 0**（R2 有 2 例，且 R1 有同源 1 例）。

**结论**：R2 中那两类"模型自身执行错误"是**旧架构的产物**，在"只产出计划字段 + 确定性渲染"下**完全消失**。R3 的残余误差是**纯调度问题**（记忆该不该刷新），这正是 R2 想分离而未能分离的东西。
