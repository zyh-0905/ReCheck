# R9NT1 integration design
Approved scope: continue the previously described native-API integration of the fixed R9 study following R9TQ1 qualification. No new algorithm or official benchmark claims.

- Keep 16 task states, 2 arms, 32 primary + 4 repeat episodes and schedule.
- Keep exact original native tools, deterministic event scheduler, and four original score definitions.
- Use qualified tools/tool_calls/role=tool path, preserving reasoning_content. No response_format, forced tool selection, parser repair, or text execution.
- Event occurs immediately after each qualifying read, before next native call, including same-response batches. Exposed state and event/call indices recorded, no hidden labels in model input.
- Native data are local. No real messages, accounts, or remote tools.
- Limits: max 10 responses/episode, max 4 tools/response, max 40 tools/episode, total 360 responses and 1440 outer tools; no extra smoke, no recycled prior quota.
- First valid research response establishes metadata identity, later responses must match. It is not model-weight authentication.
- Whole-batch validation before dispatch; real tool exceptions returned within same quota; structural/transport errors pause globally. Failed tasks are not retried or filtered.
- Honest partial-run audit and immutable journals; do not regenerate tokens on restart. No statistical selection of tasks or wins.
