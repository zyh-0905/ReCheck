# 回传包审核规则

1. 检查 EXPORT_MANIFEST 中每个文件哈希，以及 code_snapshot 与 manifest 的一致性。
2. 根据 manifest 的实验规格核对完成、未完成、失败、重复和不确定请求数；不能只统计成功响应。
3. 检查每个请求是否含隐藏 modes/gold/evaluator_rules；不能只搜索字段名，还应核对数值和文案是否意外暴露当前语义。
4. 检查四方法初始记忆和每个修复案例的前缀哈希相同；最终响应没有跨方法复用。
5. 审核 requested model、returned model、运行日期、思考/温度参数和提供方路由限制。返回名称不构成权重真实性证明。
6. 统计 JSON 错误、输出截断、网络失败、初始记忆错误、真实账单缺失。若明显存在接口问题，先修接口并建立新批次，不拼接新旧协议。
7. ReCheck：区分语义缓存错误与模型执行错误，分别看无漂移和漂移条件；计算总费用时记录共享初始化的计费/归因区别。
8. Repair readiness：不是 RepairLens 算法；分析局部修改是否遗漏、重算是否新增错误、选择调用的成本，以及当前简单任务是否过易。
9. 预实验不做录用结论，不从多次运行挑最好结果，不把软件 fixture 结果混入研究。
10. 后续论文本体、图表、结论只有在核对原始数据后更新；阴性结果同样写入审查报告。
