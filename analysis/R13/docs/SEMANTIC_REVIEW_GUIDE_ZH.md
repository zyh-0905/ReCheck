# 候选语义清点的审阅准则

本清点是源码结构规则，不是人工标注金标准。129项含同义改写和多轮派生；1032是工具/干扰增强后的注册量，绝不是新增独立任务数。

对每个任务，审阅者应分别填写：用户实际要求、目标所指实体/对象如何绑定、义务激活时点、义务结束时点、变化是否获得新用户授权、允许修改字段，以及证据不足时的UNKNOWN。

三种检查互不替代：
- EVENT：指定区间内至少发生过一个合法事件。其痕迹不必要求所有相关临时状态永远保持。
- TERMINAL：在指定义务区间末仍满足一个状态条件。区间可能是最终对话，也可能是按原规格完成某阶段后进入下一阶段的边界。
- INVARIANT：整个有效区间不能违反。事后恢复不抹去已经发生的违规。

旧目标被取消、先完成再改成新目标、用户纠正此前未完成要求，不能自动采用相同规则。区间和实体绑定不得由模型成绩反推。R13原生例子只覆盖“先完成enemy阶段，再执行friend阶段”的明确公开规格。

`automatic_guardrail_constraints`是原框架自动加入的非相关库保持约束，不等于用户声明的目标。`setting_is_prerequisite`仅是源码候选列，不认证该设置必然允许在结束时恢复。`simulator_spec_offline_only`仅供研究审阅，不得作为未来在线agent的附加信息。

当前独立人类审阅人数为0，已完成人工金标准数为0。缺少独立审阅不会被代码51项测试替代。
