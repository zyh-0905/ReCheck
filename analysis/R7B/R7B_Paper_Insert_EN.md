# Native-environment integration and controlled evidence-freshness diagnostics

Status: development / integration evidence only. This text must not be inserted as a claim of LLM-agent superiority or an official ToolSandbox benchmark score.

We pinned ToolSandbox to commit `c8571d7854316d2e1c5f288e59fe1e34e53f6dd1` and executed its local state, tool and evaluation components without replacing the Polars-backed execution context or the native tool implementations. Sixty core upstream tests passed. A separately invoked six-test execution-environment module had four passes and two failures: one concerned Python-version-specific syntax-error formatting, while the other required an external search-service credential that was intentionally not supplied. These failures are retained in the audit rather than counted as passes. Four researcher-scripted original scenario walkthroughs attained a native milestone similarity of 1.0. These are integration tests with supplied action scripts, not autonomous agent evaluations.

A controlled extension examined a single named-recipient messaging workflow across four state regimes and three placements of a previous contact lookup. All four scripted policies received the same public task, initial evidence and, when present, the same lookup observation. None received the regime label or current contact database. The native tool can return a message identifier after writing to an unassociated or reassigned telephone number. This does not violate its number-addressed API contract, but may fail the user's person-addressed goal. Consequently, a policy that revalidates only after an explicit tool error failed to prevent these silent misdeliveries.

Across the twelve constructed cases, write-time contact lookup completed all twelve without an incorrect write. Reusing an earlier observed lookup, or querying when none existed, completed ten: the two failures occurred when the lookup preceded the target's change of number. These counts characterize the selected fixtures and are not estimates of real-agent success probabilities. Observation-producing calls, initialization and final-action calls are reported separately. We do not assume that a previously obtained observation is free, current or sufficient, nor do we claim that a query guarantees safety if the environment can change again before the write.

The findings motivate separating tool acceptance, final task completion and historical side effects. They also establish a strong simple baseline: contact resolution immediately before an identity-sensitive write. The present experiment does not justify replacing that baseline with a more complex scheduler. A subsequent model study would need to establish whether this issue arises in autonomous language-mediated task execution, how policies use legitimately available observations, and whether additional control complexity yields a measurable net benefit.
