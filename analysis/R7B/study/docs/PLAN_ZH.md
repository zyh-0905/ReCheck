# R7B：材料验收与原生工具机制核验

本工作由研究端执行；零远端模型调用，不要求用户复跑。

1. 固定原ToolSandbox commit与tree，核对111项清单、53份依赖及运行时。仅使用回传安装物离线安装。
2. 运行原仓库本地common/tools测试（不运行RapidAPI测试、模型角色或CLI全套）。不修改上游源文件。
3. 用原Scenario、ExecutionEnvironment和Evaluation做4个原始任务的人工指定脚本通路验证。这是测试，不是LLM完成任务。
4. 为一种明确的联系人—消息工作流增加受控扩展。12个fixture = 4种变化（不变、无关变化、目标改号、旧号归他人）×3种已有查询时机（无、变化前、变化后）。它们不是12个独立上游任务或12个自然事故。
5. 所有策略使用相同公开请求与历史记忆，工具权限一致。对照：旧值后报错恢复、遇报错重查、每次写前重查、优先复用已经看到的查询结果。来源查询与所有外层工具调用均计数。变化前查询也可过期，保留这类反例。
6. 私有状态只用于环境修改和离线评分。策略函数不接受fixture标签、当前联系人表或正确答案。没有模型或新的ReCheck算法效果。
7. 增加手机显式异常、事后发现不能撤销写入、明确指定号码、快照分支隔离等边界测试。
8. 每份规则轨迹同时计算“最终目标达成”和“全过程无错误写入”；原生工具成功返回不可代替任务正确性。
9. 独立规则评分与原生状态比对。源码完整性前后核对，原始输入不改动，失败尝试与测试日志保留。

实现文件：native_study.py（工具/场景桥接）、score.py（不导入ToolSandbox的评分）、tests/（评分边界与集成测试）。
先写score测试并看见失败，再实现score；先写集成测试并看见失败，再接入原生函数。
